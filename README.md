# Teyvat Tasks — MVP 1.0

Неофициальный русскоязычный менеджер задач для Genshin Impact. Семь разделов: Обзор, Рутина, Персонажи, Фарм, Мои цели, Статистика и Настройки. Данные вводятся вручную и остаются в браузере. Проект не связан с HoYoverse, не запрашивает игровой логин, пароль или токен.

HTML, CSS и JavaScript с ES Modules. Без React, серверной части, внешних игровых баз, платных API и зависимостей приложения. Тесты используют встроенный Node.js test runner.

## Локальный запуск

Нужен Python 3. Откройте терминал в корне проекта, рядом с `index.html`:

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

Откройте адрес `http://127.0.0.1:8000` в браузере. Для остановки нажмите `Ctrl+C`. Если команда `python3` недоступна, используйте установленный `python` или `py` в Windows. Если порт занят, выберите другой, например 8001.

Это локальная раздача статических файлов для разработки, а не серверная часть приложения. Не открывайте `index.html` двойным щелчком: ES Modules должны загружаться через HTTP. В облачной среде доступ к локальному порту зависит от её интерфейса.

Для тестов нужен Node.js 22 или новее:

```sh
npm test
```

`npm install` не требуется: зависимостей нет. Подробный результат проверки MVP и непроверенные условия — в [docs/MVP-1.0-REPORT.md](docs/MVP-1.0-REPORT.md).

## Возможности

| Раздел | Что доступно |
| --- | --- |
| Обзор | Текущая рутина, смола, готовность материалов и ближайшие личные цели |
| Рутина | Редактируемые дневные/недельные шаблоны, счётчики, отмена, история периодов, таймеры сбросов |
| Персонажи | Ручные имя, заметки, целевой уровень, материалы с owned/needed и процентом готовности |
| Фарм | Дефицит по персонажам, ручные дни доступности, фильтры дней, планы и отметки выполнения |
| Мои цели | Категории, свои категории, приоритеты, сроки, заметки, статусы и комбинированные фильтры |
| Статистика | Действия за 7/30 игровых дней, прогресс рутины и материалов, CSS-график и таблица |
| Настройки | Сервер, тема, экспорт, предпросмотр импорта, резервная копия и подтверждаемая очистка |

Europe использует UTC+1, America UTC−5, Asia UTC+8, без DST. День начинается в 04:00 сервера, неделя — в понедельник в 04:00. Выбор сервера общий для настроек и рутины; история других серверов не удаляется.

При первом открытии «Рутины» добавляются четыре редактируемых примера, если профиль ещё не инициализировал рутину. После удаления примеры не возвращаются. Полная очистка данных начинает новый профиль; после неё рутина снова может предложить начальные примеры.

Смола рассчитывается приблизительно: +1 за 8 минут до 200. Можно уточнить замер и записать расход. Таймер не сохраняет повторные начисления, поэтому перезагрузка не удваивает восстановление. Отсчёт зависит от часов устройства и не читает игровой аккаунт.

Процент персонажа означает готовность материалов, а не фактический уровень в игре: `floor(100 × sum(min(owned, needed)) / sum(needed))`. Пустой список = 0%; список с нулевой потребностью = 100%, без деления на ноль. Запасы разных персонажей не смешиваются. Отметка плана фарма не меняет инвентарь.

Статистика пересчитывается из текущих первичных записей, без отдельных сохранённых счётчиков. Отменённые выполнения не учитываются. Дни без записей обозначаются как «нет записей», а не как доказанный пропуск. Старые агрегаты рутины без точных времён действий показаны отдельно и не получают выдуманные даты.

## Хранение и резервное копирование

Рабочий документ — один JSON с `schemaVersion: 1` в ключе `teyvat-tasks:v1`. В нём settings и восемь массивов: profiles, taskTemplates, completions, personalTasks, characters, materialGoals, farmPlans, resinSnapshots.

Версия приложения **1.0.0** и версия схемы **1** — разные вещи. Импорт версии схемы 2 или другой неизвестной версии останавливается; автоматической миграции нет.

Данные привязаны к origin браузера — сочетанию протокола, домена и порта, а не к папке сайта. Другой порт, переход с HTTP на HTTPS, другой домен или приватное окно могут показать пустое хранилище. Перенос с локального запуска на GitHub Pages выполняйте через экспорт/импорт. Несколько установок на одном origin используют общий ключ приложения.

Чтобы сохранить всё вне браузера:

1. Откройте «Настройки» → «Экспорт всех данных».
2. Проверьте, что JSON скачан в папку загрузок. Он содержит все текущие профили, настройки и коллекции, включая несохранённые изменения этой вкладки, если хранилище ранее вернуло ошибку.
3. Сохраните файл в отдельной папке или на другом носителе. JSON содержит ваши заметки: не добавляйте его в публичный Git-репозиторий. Папка `backups/` и имена экспортов `teyvat-tasks-*.json` исключены в `.gitignore`.
4. Перед крупными изменениями, очисткой данных браузера или переходом на другой адрес сделайте новый экспорт.

Приложение хранит одну дополнительную восстановительную копию в ключе `teyvat-tasks:backup:v1`. Это не вторая рабочая база, а снимок **перед импортом или очисткой**. Следующая такая операция заменяет предыдущую копию. Скачайте её заранее, если хотите оставить несколько версий.

Кнопка «Скачать резервную копию» выдаёт обычный JSON схемы 1, который можно выбрать в импорте. Локальная копия не заменяет скачанный файл: очистка данных сайта или потеря профиля браузера удалит обе локальные записи.

## Импорт и восстановление

1. Закройте другие вкладки Teyvat Tasks и сначала экспортируйте текущие данные.
2. В «Настройках» выберите JSON-файл. Ограничение — **5 МиБ**, поддерживается схема 1.
3. Проверьте предпросмотр: имя файла, тему и количество записей в каждой коллекции. Выбор файла сам по себе ничего не заменяет.
4. Для отмены нажмите «Отмена импорта». Для продолжения установите подтверждающий флажок и нажмите «Создать копию и заменить данные».
5. Приложение сначала записывает резервную копию, затем заменяет рабочий документ. Применяются и тема, и сервер импортируемого профиля. Это полная замена всех профилей и коллекций, а не слияние.
6. Проверьте результат в разделах. Для возврата скачайте резервную копию и импортируйте скачанный файл тем же способом.

Проверяются версия, JSON-типы, формат и уникальность ID внутри каждой коллекции, статусы, даты, числа и ссылки между профилями, персонажами, материалами и планами. История удалённых шаблонов рутины допустима: в ней сохранён самодостаточный снимок. Ссылки на шаблон другого профиля запрещены. Небезопасные ключи объектов и чрезмерно вложенные документы отклоняются. Безопасные дополнительные поля сохраняются.

Неверный JSON или ошибка проверки не меняют рабочие данные и не создают новую копию. Если копия не записалась из-за квоты или запрета браузера, замена не начинается. Если ошибка возникла при записи новых данных, прежний рабочий JSON и уже сделанная копия остаются доступны. Для копии нужно дополнительное свободное место в localStorage.

Если после предпросмотра изменились настройки или данные, нужен новый предпросмотр. Изменение хранилища другой вкладкой блокирует замену. Обычные записи также защищены от обнаруженного устаревшего состояния: экспортируйте сессионные изменения, обновите страницу и продолжите. Автоматического объединения изменений вкладок нет.

В блоке «Восстановление исходной записи» можно скачать исходный текст хранилища, даже если JSON повреждён. Если при резервировании запись браузера отличалась от состояния вкладки, её текст сохраняется отдельно внутри копии и доступен кнопкой «Исходная запись из копии». Такой текст может требовать ручного исправления перед импортом; приложение не удаляет его автоматически.

## Удаление данных

В «Настройках» нажмите «Удалить рабочие данные», проверьте предупреждение, установите подтверждающий флажок и нажмите «Создать копию и удалить данные». Без подтверждения очистки нет. При ошибке резервирования очистка останавливается.

Удаляются рабочие профили и коллекции; тема и настройки возвращаются к исходным. Последняя резервная копия остаётся для восстановления. Для полного удаления, включая копию, закройте вкладки приложения и очистите данные этого сайта средствами браузера. После этого восстановление возможно только из ранее скачанного JSON.

## Публикация на GitHub Pages

Публикация — отдельное решение владельца. Владелец разрешил выпуск MVP 1.0 отдельным запросом 2026-10-19. История подготовки и результаты проверок находятся в [docs/HISTORY.md](docs/HISTORY.md).

Когда выпуск согласован:

1. Запустите `npm test`, просмотрите изменения и скачайте резервную копию игровых данных.
2. Сохраните согласованные изменения в репозитории и отправьте их в GitHub только после отдельного разрешения. Убедитесь, что в отправку не попали личные экспорты.
3. В GitHub откройте репозиторий → **Settings → Pages → Source: GitHub Actions**.
4. В **Actions** выберите **Deploy static content to Pages**, нажмите **Run workflow** и укажите нужную ветку, обычно `main`.
5. Дождитесь успешных тестов и deployment. Адрес сайта будет показан в Pages и завершённом workflow.
6. Проверьте все разделы по опубликованному адресу. Для переноса локальных данных используйте экспорт/импорт, а не копирование браузерного хранилища вручную.

Workflow находится в [.github/workflows/static.yml](.github/workflows/static.yml). Он запускается вручную или при изменении файла согласованного выпуска [.github/releases/mvp-1.0.json](.github/releases/mvp-1.0.json) в `main`; обычные изменения приложения не публикуют сайт. Выпуск выполняется из `main`, поскольку защита окружения GitHub Pages запрещает публикацию из тегов. Перед подготовкой сайта запускает `npm test` на Node.js 22. Публикуемый артефакт `_site/` содержит только `index.html`, `src/` и `.nojekyll`. Пути CSS, ES Modules и навигация относительные; проверен и запуск из подпапки проектного сайта.

Старая страница сохранена как `legacy-birthday.html`, видео остались в `videos/`. Они не включаются в артефакт MVP. Публикация MVP заменяет главную страницу прежнего сайта на Teyvat Tasks.

Ожидаемый адрес: https://nezzzoru.github.io/. Состояние выпуска смотрите в GitHub Actions; успешная отправка кода сама по себе ещё не подтверждает доступность сайта. Не выбирайте публикацию всего корня ветки вместо подготовленного workflow, если хотите сохранить описанный состав артефакта.

## Структура проекта

```text
index.html                         — HTML-оболочка
src/
  main.js                          — навигация, тема и соединение модулей
  core/                            — чистая логика смолы, задач, материалов и статистики
  modules/
    time/gameClock.js              — игровые дни/недели и фиксированные смещения
    storage/storage.js             — чтение, проверка, запись и резервирование
    storage/dataTransfer.js        — формат экспорта/импорта и сообщения
    routine/                       — шаблоны и отметки рутины
    resin/                         — снимки смолы
    rendering/                     — семь разделов и компоненты интерфейса
  styles/main.css                  — адаптация и две темы
tests/                            — автоматические тесты Node.js
docs/
  PRODUCT.md                       — требования и контракт данных
  HISTORY.md                       — история выполненных этапов
  MVP-1.0-REPORT.md                — результат финальной проверки и ограничения
```

Правила разработки — в [AGENTS.md](AGENTS.md). Подробная модель — в [docs/PRODUCT.md](docs/PRODUCT.md). Пересчёты времени и смолы получают текущее время аргументом; доступ к localStorage сосредоточен в модуле хранения.
